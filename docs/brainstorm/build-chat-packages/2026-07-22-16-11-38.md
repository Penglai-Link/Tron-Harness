# Chat 子包构建设计

## 目标

将 `tron-frontend/packages` 下的六个子包构建为可由 npm 正确识别的发布产物，并建立可重复的 monorepo 版本发布流程。每个包的 `package.json` 必须指向实际生成的文件，构建后可通过 `npm pack --dry-run` 验证内容。

本次只修改构建配置、包元数据和发布工具配置，不发布包、不升级业务版本，也不改变 `@tron/chat-internal-adapter` 的私有包属性。

## 构建方案

复用项目现有的 Vite 工具链，并增加 `vite-plugin-dts` 生成 TypeScript 声明。

- `@tron/chat-core`、`@tron/chat-openapi-adapter` 和 `@tron/chat-internal-adapter` 构建为 ESM JavaScript，并生成 `.d.ts`。
- `@tron/chat-react` 使用 Vite React 插件构建，React 相关依赖保持外部依赖，并生成 ESM JavaScript、CSS 和 `.d.ts`。
- `@tron/chat-vue` 使用 Vite Vue 插件构建 Vue SFC，Vue 相关依赖保持外部依赖，并生成 ESM JavaScript、CSS 和 `.d.ts`。
- `@tron/chat-theme` 使用 Sass CLI 将 `theme.scss` 编译为 `dist/theme.css`，同时复制原始 SCSS 和声明文件到 `dist`。

所有包的输出目录均为各自的 `dist/`。每次构建前清理该目录。

Turborepo 负责按 workspace 依赖图执行构建、测试和打包检查。`build` 任务依赖上游包的 `build`，缓存 `dist/**`。根 npm 脚本提供统一入口，Makefile 只调用这些入口。

## 包元数据

每个子包的 `package.json` 增加：

- `files`，只包含 `dist` 和需要发布的说明文件；
- `main`、`module`、`types`，指向 `dist` 中的真实文件；
- 条件式 `exports`，明确 JavaScript、类型和样式入口；
- `build` 脚本；
- `prepublishOnly`，确保发布前重新构建。

引用 `@tron/chat-core` 的 adapter、React 和 Vue 包必须声明 `@tron/chat-core` 依赖。React、React DOM 和 Vue 作为 peer dependency，避免消费项目加载重复框架运行时。

## 版本与发布

使用 Changesets 管理公开包的版本、变更记录和 npm 发布：

- `.changeset/config.json` 使用独立版本策略；
- `changeset` 创建变更说明；
- `version-packages` 更新版本和 Changelog；
- `release` 先通过 Turbo 构建，再执行 `changeset publish`；
- `@tron/chat-internal-adapter` 保持私有，不参与 npm 发布。

发布目标为公司 Nexus hosted npm 仓库。仓库地址通过 npm 配置或命令参数提供，认证信息只通过进程环境注入。

## Makefile 接口

根 Makefile 增加统一的子包构建目标。Makefile 调用根 npm 脚本，Turbo 根据 workspace 依赖图自动确定顺序：

1. `chat-core`
2. `chat-theme`
3. `chat-openapi-adapter`
4. `chat-internal-adapter`
5. `chat-react`
6. `chat-vue`

Makefile recipe 不依赖 `.ONESHELL`，保持 GNU Make 3.81 兼容。

## 验证

实现完成后必须通过：

1. 根 Makefile 的 Turbo 子包构建目标；
2. `make fe-check`；
3. `make fe-unit-test`；
4. `npm pack --dry-run --workspaces`。

验收时确认每个包的 `exports` 所指文件均存在，tarball 不包含源码测试、演示页面或 Vite 开发配置。

## 安全约束

Nexus 凭据只允许在真正发布时通过临时环境变量注入。凭据不得写入仓库、设计文档、构建配置、日志或提交。已经通过非密钥通道共享的凭据应在 Nexus 中轮换后再用于正式发布。
