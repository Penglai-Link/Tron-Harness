# Unassigned Space Authorization

## Context

- Request: authenticated users without assigned spaces must see a page asking a responsible owner to authorize workspace access instead of being able to operate the console.
- Existing auth model already exposes `session.user.spaceCodes`.
- Existing protected routing only checked authenticated versus unauthenticated status, so empty-space users could enter the shell.

## Options Considered

- Shell-only empty switcher guard: simple, but still lets non-shell protected routes and persisted shell state leak through.
- Global protected-route guard using `session.user.spaceCodes`: blocks every protected route before shell, navigation, workspace switcher, and business pages render.
- Per-page guards: high duplication and easy to miss pages.

## Decision

Use the global protected-route guard. A user is considered unauthorized for console operation when the authenticated session exists but `session.user.spaceCodes` is empty. The app renders a standalone authorization page with the signed-in account, next-step copy for the responsible owner, and a logout action. It does not render `TronShell`, primary navigation, workspace switcher, settings shortcuts, or business page content.

## Scope

- Add a frontend-only authorization wait page.
- Block all protected routes for authenticated users without assigned spaces.
- Keep normal anonymous redirect, assigned-space login, OAuth, refresh, reload, and logout behavior unchanged.
- Add Playwright coverage in the existing auth smoke suite.

## Approval

- status: approved_with_defaults
- rationale: the request directly states the required behavior and the repository already provides the needed `spaceCodes` session contract.
