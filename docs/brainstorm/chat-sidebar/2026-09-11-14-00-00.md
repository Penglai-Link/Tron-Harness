# 项目化会话上下文规格

## 目标

在全局左侧栏提供项目和会话历史。用户创建会话前必须选择项目。项目关联当前工作区中的多个 App，项目下的全部会话可以访问这些 App 的本地目录和仓库上下文。

项目结构如下：

```text
工作区
└─ 项目
   ├─ App A
   ├─ App B
   └─ 会话
      ├─ 会话 1
      └─ 会话 2
```

项目是会话上下文的父级，不是工作区的别名。工作区继续负责权限、资源隔离和项目/App 的归属范围。

## 用户流程

1. 用户在任意页面点击全局左侧栏的“新对话”。
2. 系统打开项目选择器，显示当前工作区中可访问的项目；用户可搜索、选择项目，或进入项目创建弹窗。
3. 选择项目后，系统创建会话并跳转到 `/chats?sessionCode={sessionCode}`。
4. 聊天页沿用现有的会话激活、消息加载、输入框聚焦和流式响应逻辑。
5. 左侧栏按“项目 -> 会话”展示当前工作区的会话；项目节点支持展开和收起。
6. 用户创建或编辑项目时，从当前工作区的 App 中添加多个关联 App。第一个 App 自动成为主要 App；用户可以将任一关联 App 设为主要 App。

项目必须至少关联一个处于 Active 状态且用户有访问权限的 App。项目创建、项目编辑和会话创建均不能跨工作区选择 App 或项目。

## 上下文规则

会话仅保存 `projectCode`，不保存 App 快照。每次发送消息时，后端重新查询该项目当前关联的 App，因此项目配置变更会作用于已有会话的下一次执行。

每个项目关联 App 的顺序由 `position` 决定，且恰好一个关联 App 的 `isPrimary` 为真。

- 主要 App 的 `localDirectory` 是未指定目录时的默认工作目录。
- 关联 App 的全部 `localDirectory` 组成该会话允许访问的根目录集合。
- 关联 App 的 `repositoryUrl`、`defaultBranch` 和名称作为可供智能体判断的项目上下文。
- 用户或智能体指定相对路径时，路径相对主要 App 的本地目录解析。
- 用户或智能体指定绝对路径、工具搜索根目录或命令工作目录时，后端确认目标路径位于任一允许根目录内。
- 不在允许根目录内的读取、搜索、编辑、枚举和命令执行必须拒绝，返回明确的路径越界错误。
- 主要 App 的本地目录不存在、项目没有关联 App、关联 App 被归档，或当前用户失去项目/App 访问权限时，后端拒绝本次运行并返回可显示的错误。

已有不关联项目的会话继续使用原有 `appCode` 和工作区逻辑。新建手工会话必须关联项目；任务、自动化和终端会话维持当前创建路径，除非后续需求要求它们也绑定项目。

## 数据模型

新增项目领域，所有主键使用现有 ID 提供器生成，外部代码使用稳定的 `PROJECT-{id}` 格式。

```text
projects
├─ id
├─ project_code
├─ workspace_code
├─ name
├─ status: ACTIVE | ARCHIVED
├─ created_at
└─ updated_at

project_app_links
├─ id
├─ project_code
├─ app_code
├─ position
└─ is_primary

chat_sessions
└─ project_code nullable
```

约束：

- 同一工作区内项目名称唯一，比较时忽略首尾空白。
- 同一项目不能重复关联同一个 App。
- 项目关联 App 的位置唯一且从零开始连续排序。
- 每个有 App 的项目恰好有一个主要 App。
- `project_app_links` 中的 App 必须属于项目的工作区。
- 创建手工会话时，项目必须存在、为 Active，且属于请求的工作区。

项目删除采用归档。归档项目不能创建会话，也不能继续驱动既有会话运行；历史会话和消息保留。App 归档或移除项目关联后，下一次运行立即使用最新关联状态。

## API

新增项目 API，沿用统一响应体 `{ code, message, data }` 和分页响应约定。

```text
GET    /api/v1/projects/workspaces/{workspaceCode}
POST   /api/v1/projects/workspaces/{workspaceCode}
GET    /api/v1/projects/{projectCode}
PATCH  /api/v1/projects/{projectCode}
POST   /api/v1/projects/{projectCode}/archive
GET    /api/v1/projects/workspaces/{workspaceCode}/options
```

创建和更新请求包含项目名称及有序 App 关联：

```json
{
  "name": "Tron Console",
  "appCodes": ["APP-frontend", "APP-backend"],
  "primaryAppCode": "APP-frontend"
}
```

`POST /api/v1/chats/sessions` 增加 `projectCode`。手工创建会话必须传递该字段；后端根据项目动态解析 App 上下文。会话详情和列表响应增加可选 `projectCode`，以支持左侧栏分组。

向智能体发起运行时，聊天服务以 `projectCode` 解析一份 `ProjectExecutionScope`，包含主要 App、所有关联 App 及允许目录根集合。运行上下文和工具调用不接受来自前端的未授权目录列表。

## 后端实现边界

新增 `project` 领域、应用服务、SQLite 仓储、迁移和 HTTP 路由。项目服务负责工作区权限、App 归属校验、主要 App 一致性和项目归档。

聊天服务在创建手工会话时验证 `projectCode`。消息发送时再次解析项目，以保证已有会话使用最新的 App 配置。`ChatSession` 和相关持久化映射增加可空 `project_code`。

当前 `AgentExecutionScope` 只包含单个 `app_code` 和 `local_directory`。改为保留主要 App 字段，同时新增只读的关联 App 描述和允许目录根集合。运行时仍将主要目录传给仅支持单个工作目录的适配器；编码工具通过统一路径解析器验证所有路径都在允许根集合内。

工具的路径校验必须覆盖文件读取、搜索、目录枚举、写入、编辑、补丁、命令执行和显式工作目录。校验在路径规范化后进行，禁止通过 `..`、符号链接或绝对路径跳出允许根目录。

动态会话项目分组不属于持久化导航树。它由 Shell 独立渲染，因此不修改 `shellNavigation.ts`、内置 SQLite 菜单迁移或导航管理后台。

## 前端结构

全局会话侧栏放在用户指定的目录，作为 `TronSidebar` 的领域内容插槽：

```text
tron-frontend/src/shared/layout/chat/
├─ components/
│  ├─ ChatSidebarPanel.tsx
│  ├─ NewChatButton.tsx
│  ├─ ProjectSessionGroup.tsx
│  ├─ ProjectSelector.tsx
│  └─ SessionHistoryItem.tsx
├─ hooks/
│  ├─ useChatSessionNavigation.ts
│  └─ useProjectSessionSidebar.ts
├─ model/
│  └─ chatSidebarTypes.ts
└─ index.ts

tron-frontend/src/domain/project/
├─ api/
├─ components/
│  ├─ ProjectCreateDialog.tsx
│  ├─ ProjectAppList.tsx
│  └─ ProjectEditDialog.tsx
├─ hooks/
├─ model/
├─ pages/
└─ index.ts
```

`shared/layout/chat` 只负责左栏的会话创建、项目选择、项目会话列表和路由跳转。项目 CRUD、数据请求、表单校验和错误映射放在 `domain/project`。聊天运行态、流式响应、消息列表和会话详情继续保留在 `domain/chat`。

侧栏使用当前工作区选择器提供的工作区代码。工作区变更时，项目和会话列表刷新，展开状态按工作区隔离。点击会话跳转到现有聊天 URL；聊天页从 URL 激活会话，保留当前的流观察器切换与自动聚焦行为。

创建项目和选择项目使用既有 Dialog、Combobox、Button、ScrollArea 和 Tooltip 基础组件。全部用户可见文本加入中英文翻译资源。

## 错误处理

| 场景 | 行为 |
| --- | --- |
| 当前工作区没有项目 | 项目选择器展示空状态和创建项目入口；不创建会话。 |
| 项目没有可用 App | 阻止保存和创建会话，并说明需要至少关联一个可用 App。 |
| 项目已归档或无访问权限 | 阻止创建或发送；刷新左侧栏。 |
| App 被归档、移除或目录不存在 | 下次运行失败，返回关联 App 和原因；用户可编辑项目后重试。 |
| 路径超出关联 App 根目录 | 工具调用失败，不访问目标路径，并报告允许的项目范围。 |
| 项目更新与会话运行并发 | 已开始的运行使用其构建时上下文；下一次发送重新读取项目。 |

## 验收与测试

- 用户未选择项目时，不能创建手工会话。
- 项目创建弹窗仅展示当前工作区可访问的 App，至少选择一个 App。
- 第一个 App 自动成为主要 App；用户可切换主要 App，且每个项目始终只有一个主要 App。
- 新会话带有 `projectCode`，出现在对应项目节点下，点击后进入既有聊天行为。
- 项目新增、移除或切换主要 App 后，已有会话下一次发送使用最新 App 集合和默认目录。
- 跨关联 App 的读取、搜索、编辑和命令执行成功；访问关联根目录外路径失败。
- 切换工作区时，左侧栏不展示其他工作区的项目和会话。
- 旧会话保持原有行为。
- 前端通过 `make fe-check`、相关单元测试和 Playwright 覆盖；后端通过 `make be-test` 覆盖项目 API、权限、会话项目校验和路径授权。
- 浏览器验证覆盖中英文、桌面侧栏、移动端抽屉、项目选择、创建会话和会话切换。

## 非目标

- 本期不把项目动态会话树写入导航管理后台。
- 本期不要求任务、自动化或终端会话绑定项目。
- 本期不复制 App 的目录、仓库地址或分支到项目记录中；项目始终引用 App 的当前配置。
