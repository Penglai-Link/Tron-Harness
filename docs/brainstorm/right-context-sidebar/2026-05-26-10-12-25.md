# Right Context Sidebar

## Context

The console shell already supports page-provided `rightPanel` content. Chat and Observability use it today. The current implementation renders a fixed 360px right column when content exists, but it has no shell-level collapse behavior. On smaller screens, the panel falls below the main content instead of acting like a drawer.

The requested feature is a conditional right-side context sidebar. It must be available only on pages that provide contextual content. It must not appear on global configuration pages.

## Decision

Upgrade the existing `TronShell.rightPanel` path into a shell-level right context sidebar. Do not create a separate page-level sidebar system.

Pages keep ownership of the content by calling `useConsoleShellConfig({ rightPanel })`. The shell owns placement, collapse state, desktop layout, mobile drawer behavior, and accessibility controls.

## Scope

In scope:

- Console shell right sidebar behavior.
- Desktop expanded and collapsed states.
- Mobile overlay drawer behavior.
- Shell store state for right sidebar collapse.
- Shell i18n labels for right sidebar actions.
- Regression checks for existing right-panel pages: Chat, Observability, and Shared Shell Preview.

Out of scope:

- `SettingsShell` and global configuration pages.
- Migrating page-owned inspectors in graph, task detail, automation detail, memory, prompt, variables, skills, knowledge base, or app detail pages.
- Backend API changes.
- New right sidebar content for pages that do not already provide it.

## Desktop Behavior

When a console page provides `rightPanel`, the shell shows a right context sidebar.

Expanded state:

- The sidebar uses the current 360px width.
- The main content and sidebar share the shell grid.
- The sidebar includes a visible collapse control near its top edge.

Collapsed state:

- The sidebar content leaves the layout.
- Main content regains the full available width.
- A small button remains pinned to the right edge of the viewport.
- The button uses a left-pointing icon such as `<` or `PanelRightOpen` and opens the sidebar.
- No collapsed content rail remains.

No-content state:

- If `rightPanel` is `undefined`, the shell renders no sidebar and no right-edge toggle.
- This lets pages such as Observability close their inspector completely.

## Mobile Behavior

Mobile must not hide the feature.

When a page provides `rightPanel`, the shell shows it as a right-side overlay drawer. The drawer covers the main content and does not flow below it.

The drawer closes through:

- close button,
- backdrop click,
- `Escape`,
- route change.

The drawer should keep focus and pointer behavior predictable. The first implementation can use the existing shell overlay patterns and does not need a separate animation library.

## State

Add `rightSidebarCollapsed` and `setRightSidebarCollapsed` to `appShellStore`.

Persist `rightSidebarCollapsed` under the existing `tron-app-shell` store, matching the left sidebar persistence model.

The persisted collapsed state applies only when the active page provides `rightPanel`. Pages without `rightPanel` must not show a stale right-edge toggle.

Mobile drawer open state should stay local to `TronShell`. It should reset on route change.

## Page Integration

Keep the current page contract:

```tsx
useConsoleShellConfig({ rightPanel });
```

The page defines content and can remove it by passing `undefined`. The shell decides how to render that content across desktop and mobile.

Do not add `rightPanel` to static route metadata in the first version. Existing page-driven state is more flexible for inspectors, tabs, selected rows, and close actions.

## Accessibility

Controls need clear labels:

- Open right sidebar.
- Collapse right sidebar.
- Close right sidebar.

Desktop toggle buttons should expose `aria-expanded` or `aria-pressed` consistently with the left sidebar controls.

Mobile drawer should have a dialog-like label and close on `Escape`.

## Alternatives Considered

### Static Right Column

This keeps the current implementation and only adds page content. It is the smallest change, but it does not satisfy the collapse requirement and produces weak behavior on smaller screens.

### Page-Owned Panels Everywhere

Each page could own its own right panel and collapse logic. This works for complex pages, but it duplicates layout behavior and makes consistency harder. The repository already has shell-level `rightPanel`, so this path adds avoidable drift.

### Shell-Level Collapsible Sidebar

This is the selected approach. It reuses the existing extension point, keeps content page-specific, and centralizes layout behavior in one shell.

## Implementation Notes

Primary files:

- `tron-frontend/src/shared/layout/Shell.tsx`
- `tron-frontend/src/store/appShellStore.ts`
- `tron-frontend/src/i18n/locales/en-US/shell.ts`

Expected verification:

- `make fe-check`
- Desktop visual check for pages with and without `rightPanel`.
- Desktop check with both left and right sidebar collapsed.
- Mobile check for drawer open, close, backdrop, `Escape`, and route reset.
- Settings pages check to confirm no right sidebar appears.

## Open Questions

None. The agreed baseline is: desktop collapse removes the sidebar from layout and leaves only a right-edge open control; mobile uses an overlay drawer; global configuration pages do not use the right sidebar.
