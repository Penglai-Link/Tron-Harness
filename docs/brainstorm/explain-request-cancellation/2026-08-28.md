# 命令解释请求取消设计

## 目标

命令解释弹窗在点击弹窗外空白、点击关闭或开始刷新时，立即取消前端 SSE 请求，并释放后端 ChatService 会话中的 active run，避免下一次解释请求收到 `chat session already has an active run`。

## 方案

`ExplainController` 继续用每次请求独立的 `AbortController` 管理 SSE 生命周期，并通过可选的 `AITransport.cancel()` 通知宿主停止后端 run。终端页面实现该能力：取消传入 signal 对应的 stream，同时查询当前 session 的 active run 并调用 `stopRun`。取消失败不阻塞弹窗关闭，避免网络异常让 UI 卡住。

弹窗外 `pointerdown` 与关闭按钮统一调用 `ExplainController.close()`；刷新先取消旧请求，再启动新请求。普通终端聊天不调用该取消入口，因此行为保持不变。

## 测试

- 控制器关闭时，当前解释请求的 signal 必须 aborted，且只触发一次取消回调。
- 点击弹窗外空白和关闭按钮都必须走同一取消路径。
- 刷新必须取消旧请求后才能开始新请求。
- 运行 `make fe-unit-test` 与 `make fe-check`。
