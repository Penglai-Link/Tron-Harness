# Chat composer attachment layout

## Goal

Show pending attachments inside the top of the chat composer. Keep the composer readable and make the attachment type obvious before sending.

## Interaction

- Render the pending-attachment strip above the text input, inside the composer surface.
- Render image attachments as static thumbnails. Use the attachment's `imageUrl` when available; otherwise load the uploaded image through the existing attachment downloader.
- Render non-image attachments as a compact card with a file icon, truncated file name, file type label, and a remove button.
- Do not open a hover or focus preview for any attachment.
- The remove button deletes only its own pending attachment and exposes an accessible label containing the attachment name.
- Clear the pending-attachment strip after a message is successfully submitted. Preserve the existing failure path that restores attachments when submission fails.

## Data and component boundaries

Reuse `ChatMessageAttachment`, `isImageAttachment`, and the existing attachment downloader. Keep pending-attachment rendering in `TronChatRuntimeWindow` or a small package-local component; do not add a new shared primitive or dependency. Keep message-history attachment rendering unchanged.

The display type comes from `contentType` for image detection and from the filename/content type for the non-image type label. Missing names fall back to the attachment title, summary, or id, matching the current label behavior.

## Visual rules

Use the existing chat theme tokens and attachment styles. The strip supports multiple attachments with wrapping, a fixed thumbnail bound, ellipsis for long names, and a visible remove control. Preserve the existing composer row for attach/model/send controls below the text input.

## Verification

- Unit-test image and non-image pending attachments in the runtime window.
- Assert that removing one attachment leaves the others intact.
- Assert that a successful send leaves no pending attachment chip; failed submission continues to restore the source attachments.
- Run the required frontend checks through the repository Makefile.
