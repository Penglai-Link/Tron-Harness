# Frontend UI Component Guidelines

## Objective

Make `tron-frontend/src/components/ui` the first choice for reusable page controls and establish a maintained document that describes the available primitives.

## Scope

- Update `tron-frontend/AGENTS.md` with the required component selection and documentation rules.
- Update `tron-frontend/docs/spec/react-coding-spec.md` with implementation guidance and exceptions.
- Add `tron-frontend/docs/spec/ui-components.md` with the current component catalog, exported APIs, usage examples, and maintenance workflow.
- Do not refactor existing pages or move domain-specific components.

## Design

Page and domain component work must begin by checking the components in `src/components/ui`. Existing primitives should be composed and styled through their public APIs. A custom component is appropriate when the behavior is domain-specific, and a new UI primitive is appropriate only when no existing primitive can support the interaction without leaking implementation details or compromising accessibility.

The component catalog is the source of truth for the directory's public inventory. Every added or materially changed UI primitive must update the catalog in the same change. Each entry records its purpose, exported API, and usage guidance. New components must also document type safety, keyboard/accessibility behavior, internationalization considerations, and focused tests.

## Validation

- Verify every documented component file exists and every listed primary export matches the implementation.
- Check the Markdown for placeholders, contradictory rules, and stale component names.
- Run the frontend verification through the repository Makefile with `make fe-check`.
