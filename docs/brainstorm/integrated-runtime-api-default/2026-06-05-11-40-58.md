# Spec: Integrated Runtime Defaults To API Mode

## Summary

Change the integrated Make targets so `make app-build` and `make app-run` always produce a frontend that talks to the backend API by default. Keep standalone frontend workflows unchanged.

## Problem

The current integrated runtime builds frontend assets into the backend and serves both layers from one port, but the frontend still defaults to mock mode unless callers export extra `VITE_TRON_*_DATA_SOURCE` variables. That makes the one-command path feel incomplete and easy to misread.

## Goals

- Make `make app-build` and `make app-run` behave like true integrated runtime commands.
- Keep frontend API requests same-origin so the browser follows the backend port selected by `PORT`.
- Preserve standalone frontend commands such as `make fe-dev`, `make fe-build`, and ad hoc mock-mode testing.

## Non-Goals

- Do not change Vite dev-server proxy behavior for `make fe-dev`.
- Do not bake `http://127.0.0.1:${PORT}` into production frontend assets.
- Do not change per-domain data-source behavior outside integrated targets.

## Design

### Makefile behavior

- `make app-build` will inject `VITE_TRON_DATA_SOURCE=api` during the frontend build.
- It will also inject `VITE_TRON_AUTH_DATA_SOURCE=api` and `VITE_TRON_ADMIN_DATA_SOURCE=api` explicitly so integrated startup does not inherit stale shell overrides for those domains.
- `VITE_TRON_API_BASE_URL` will stay empty. The frontend will call same-origin `/api/...`, so requests automatically follow whichever backend port `make app-run PORT=...` starts.
- `TRON_FRONTEND_OUT_DIR` behavior stays unchanged.

### Command semantics

- `make app-build` and `make app-run` will now share the same integrated-runtime contract: built assets default to API mode.
- `make app-run` will keep depending on `app-build`, so the runtime path stays one command.
- `make fe-dev` remains the place where `TRON_FRONTEND_API_PROXY_TARGET` matters. Integrated builds do not need that proxy setting because they are served by the backend itself.

### Documentation and contract updates

- Update the integrated frontend runtime feature spec and acceptance docs to replace the old “preserve existing data-source choices” contract with the new “integrated targets default to API mode” contract.
- Update the backend Makefile contract test so it asserts the new required environment injection instead of forbidding it.
- Keep the wording clear that standalone frontend targets still preserve their own defaults.

## Risks And Mitigations

- Risk: tests or local habits that expected integrated builds to stay in mock mode will flip behavior.
- Mitigation: limit the default change to `app-build` and `app-run`, and keep all standalone frontend targets unchanged.

- Risk: shell-level domain overrides may still surprise integrated builds.
- Mitigation: explicitly set the known high-impact overrides for auth and admin to `api` inside the integrated build command.

## Validation

- Run the backend Makefile contract test that checks integrated target semantics.
- Run `make app-build` to verify the frontend still builds into backend resources.
- Run `make app-run PORT=8080` and smoke-check that the backend serves the integrated frontend on the same port.

## Open Decisions Resolved

- Apply the default-API behavior to both `app-build` and `app-run`, not `app-run` alone, so integrated commands share one consistent contract.
