# Database Design: Task Management

## Database Decision

- status: approved
- impact: create task-management persistence tables and seed rows
- approved_by: clouds3n
- approved_at: 2026-05-16

## Existing Schema Impact

The feature adds task tables only. It reads existing `workspaces` and workspace effective users through service validation and does not alter workspace, user, role, or auth tables.

## Proposed Schema

### tasks

- change_type: create
- fields: `id`, `task_code`, `workspace_code`, `parent_task_code`, `title`, `description`, `status`, `priority`, `progress_value`, `progress_mode`, `created_at`, `updated_at`
- constraints: unique `task_code`; status, priority, and progress_mode check constraints; `progress_value` between 0 and 100
- indexes: `workspace_code/status`, `parent_task_code`
- notes: `task_code` is generated by the backend and used by frontend navigation.

### task_user_assignments

- change_type: create
- fields: `id`, `task_code`, `user_code`, `assigned_at`
- constraints: unique `task_code` and `user_code`
- indexes: `task_code`, `user_code`
- notes: effective-user validation happens in application service against workspace-management.

## Relationships And Cardinality

One Active workspace owns many tasks. One task can have zero or one parent task and many direct child tasks. Parent and child tasks must share one workspace. One task can have many assigned users. Agent and app arrays are not persisted in v1.

## Migration Plan

Add one migration after workspace-management migrations. Existing databases receive empty task tables. Seed runs only when the tasks table is empty and includes active examples under `TRON_CORE`.

## Query And Performance Plan

Primary queries filter by workspace, status, search, priority, parent task, and assignee. Kanban reads derive columns from backend status enums. Detail reads assemble one task with assigned users, reserved empty integration arrays, parent summary, and direct child summaries.

## Data Governance

Task APIs require authentication. Workspace and user references are stable external codes. Deletes and archives are out of scope for v1.

## Test Data And Fixtures

Seed data includes Backlog and InProgress task examples under the seeded workspace. Tests use temporary SQLite database paths for isolated mutation coverage.
