# 事实（FACT）

未来可以在核对权威性、稳定性和时效后使用的长期事实。偏好、规则、决策、操作流程、风险、助手猜测和已有更好实时来源的普通状态不属于此类。

## 正文结构

`text` 使用普通 Markdown，按下面顺序表达。标签和可读内容跟随 `metadata.language`；以下为中文模板，不能原样保存占位文字。

```md
事实：<有明确主体和边界的事实结论>

来源权威：<来源支持该结论的理由>

稳定性与时效：<观察、生效、复核或替代条件>

用法：<未来如何使用>

例外：<过时、不相关或不安全时不采用>

证据：<简短来源摘要>
```

## 类型字段

- `factSubject`：事实描述的实体、系统或产物。
- `sourceAuthority`：来源为什么可以证明该事实。
- `stability`：stable、time_sensitive、volatile 或 historical。
- `timeBoundary`：生效时间、观察日期、复核窗口或替代条件。
- `reviewAt`：stability 为 time_sensitive 或 volatile 时必须提供复核日期。

## 语义键与证据

`semanticKey` 的结构：

```text
fact:<范围编码>:<事实主题>:<事实名称>
```

尖括号内容替换为稳定的小写 ASCII 段，保持同主题、同用途的键稳定；复核或补强时更新原记录，不靠改写措辞新建近似副本。

`sourceRefs` 要求：经确认的陈述、正式资料、持久系统记录或有稳定定位的权威来源。工具结果只证明其直接观察到的现象，不自动具备长期权威性。

## 合格示例

按 2026-06-03 的已批准政策，新增客户数据存储区域需先审查；政策或区域列表变化时复核。

对应 `metadata.typeSpecific` 示例：

```json
{
  "factSubject": "客户数据存储区域审查",
  "sourceAuthority": "已批准的数据驻留政策",
  "stability": "time_sensitive",
  "timeBoundary": "政策观察于 2026-06-03，变更时复核",
  "reviewAt": "2026-09-03"
}
```

这是局部内容示例，实际保存还需补全 SKILL.md 中的范围、标题、状态、语言和真实来源，不是完整工具调用。

## 不合格示例

“这个区域已经批准，因为助手认为没问题。”

原因：没有权威来源、明确主体、时效或复核日期。
