# 风险（RISK）

有证据且能指导规避动作的长期风险。需说明触发、影响、责任归属和规避；泛泛担忧、未经证实的猜测和没有应对动作的缺陷报告不属于此类。

## 正文结构

`text` 使用普通 Markdown，按下面顺序表达。标签和可读内容跟随 `metadata.language`；以下为中文模板，不能原样保存占位文字。

```md
风险：<什么条件可能导致什么影响>

影响：<谁或什么受损>

规避：<降低风险的具体动作>

程度与归属：<严重程度和负责主体>

适用条件：<何时改变后续行为>

例外：<风险不相关或已被消除的情况>

证据：<事件或权威警示的出处>
```

## 类型字段

- `riskTrigger`：风险触发条件。
- `impact`：具体损失或失败。
- `avoidance`：可以执行的规避动作。
- `severity`：严重程度，例如 high、medium、low。
- `owner`：负责的人、团队或治理范围。

## 语义键与证据

`semanticKey` 的结构：

```text
risk:<范围编码>:<触发条件>:<影响领域>:<规避动作>
```

尖括号内容替换为稳定的小写 ASCII 段，保持同主题、同用途的键稳定；复核或补强时更新原记录，不靠改写措辞新建近似副本。

`sourceRefs` 要求：事故、审查发现、安全说明、数据损失报告或负责人的明确风险说明。纯猜测不进入已批准风险。

## 合格示例

原始日志进入长期记忆可能泄漏敏感上下文；保存脱敏结论和证据指针，避免复制原文。

对应 `metadata.typeSpecific` 示例：

```json
{
  "riskTrigger": "将原始日志写入长期记忆",
  "impact": "敏感上下文在未来检索中泄漏",
  "avoidance": "仅保存经过脱敏的结论和证据指针",
  "severity": "high",
  "owner": "记忆治理负责人"
}
```

这是局部内容示例，实际保存还需补全 SKILL.md 中的范围、标题、状态、语言和真实来源，不是完整工具调用。

## 不合格示例

“服务商可能失败，小心一点。”

原因：没有证据、具体影响、责任归属或可执行规避动作。
