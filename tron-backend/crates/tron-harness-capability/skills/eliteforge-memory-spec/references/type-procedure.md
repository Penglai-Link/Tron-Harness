# 操作流程（PROCEDURE）

触发条件再次出现时可重复执行的流程。必须有前提、至少两步、可观察的成功标准、验证和回退。临时计划、一次性命令和未验证想法不属于此类。

## 正文结构

`text` 使用普通 Markdown，按下面顺序表达。标签和可读内容跟随 `metadata.language`；以下为中文模板，不能原样保存占位文字。

```md
流程：<流程名称与目的>

触发条件：<什么时候执行>

前提：<权限、输入、文件或运行状态>

步骤：<按顺序写可重复动作，至少两步>

验证：<如何证明成功>

回退：<失败或前提缺失时怎么办>

例外：<哪些情况不适用>

证据：<经验证的操作依据>
```

## 类型字段

- `trigger`：触发条件。
- `successCriteria`：可观察的成功结果。
- `validation`：检查、测试或复核方式。
- `rollbackOrFallback`：失败或前提缺失时的回退。
- `prerequisites`：非空前提数组。
- `steps`：有序步骤数组，至少两项。

## 语义键与证据

`semanticKey` 的结构：

```text
procedure:<范围编码>:<专业领域>:<触发条件>:<流程名称>
```

尖括号内容替换为稳定的小写 ASCII 段，保持同主题、同用途的键稳定；复核或补强时更新原记录，不靠改写措辞新建近似副本。

`sourceRefs` 要求：操作手册、项目指令、已确认的实现报告、重复成功的执行或经过复核的故障恢复；单次失败不等于验证。

## 合格示例

记忆批准前先核对来源、范围和用途，再检索重复冲突；检查不通过则保留候选。

对应 `metadata.typeSpecific` 示例：

```json
{
  "trigger": "记忆候选准备进入生效状态",
  "successCriteria": "来源、范围、类型和去重检查均通过",
  "validation": "核对内容规范和当前检索结果",
  "rollbackOrFallback": "保留候选并说明未通过原因",
  "prerequisites": [
    "候选记录可读",
    "证据可定位"
  ],
  "steps": [
    "核对来源、范围和未来用途",
    "检索重复冲突并复核类型字段"
  ]
}
```

这是局部内容示例，实际保存还需补全 SKILL.md 中的范围、标题、状态、语言和真实来源，不是完整工具调用。

## 不合格示例

“运行一些命令，没报错就算成功。”

原因：没有明确触发、输入、复用步骤、验证或回退。
