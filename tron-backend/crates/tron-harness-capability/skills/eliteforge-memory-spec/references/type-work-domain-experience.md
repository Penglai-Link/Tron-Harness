# 工作领域经验（WORK_DOMAIN_EXPERIENCE）

专业领域内可复用的失败模式、根因、修正、验证与预防。必须有跨项目价值；无法指出专业领域时不使用此类。用户偏好、项目规则、原始错误和没有复用修正的一次失误不属于此类。

## 正文结构

`text` 使用普通 Markdown，按下面顺序表达。标签和可读内容跟随 `metadata.language`；以下为中文模板，不能原样保存占位文字。

```md
经验：<遇到什么条件，采取什么动作避免什么失败>

根因：<实际原因及证据边界>

修正动作：<以后具体怎么做>

验证：<修正成功的依据>

预防：<可复用的检查或习惯>

例外：<不能泛化到哪些情况>

证据：<故障与验证来源>
```

## 类型字段

- `trigger`：经验适用的触发条件。
- `failureMode`：要避免的失败模式。
- `rootCause`：发生原因。
- `correctiveAction`：以后采用的修正动作。
- `validationResult`：修正如何被验证。
- `recurrencePrevention`：防止再次发生的检查或约束。

## 语义键与证据

`semanticKey` 的结构：

```text
work-domain-experience:<专业领域>:<触发条件>:<失败模式>
```

尖括号内容替换为稳定的小写 ASCII 段，保持同主题、同用途的键稳定；复核或补强时更新原记录，不靠改写措辞新建近似副本。

`sourceRefs` 要求：尽可能同时提供故障证据和修正验证证据。只有一次现象、未知根因或未验证动作时保留笔记或候选。

专业领域写入 `metadata.subject`、`metadata.purpose` 或语义键，不随意增加 `typeSpecific` 字段或编造 `scopeCode`。

## 合格示例

执行受环境影响的验证时，先固定所需上下文，避免把继承的宿主配置误判为产品缺陷。

对应 `metadata.typeSpecific` 示例：

```json
{
  "trigger": "执行受外部环境配置影响的验证",
  "failureMode": "把宿主设置引起的失败误判为产品缺陷",
  "rootCause": "验证进程继承了未声明的宿主配置",
  "correctiveAction": "先固定验证需要的环境上下文",
  "validationResult": "显式配置后同一检查稳定通过",
  "recurrencePrevention": "修改产品前先核对验证环境"
}
```

这是局部内容示例，实际保存还需补全 SKILL.md 中的范围、标题、状态、语言和真实来源，不是完整工具调用。

## 不合格示例

“验证经常失败，多运行几次。”

原因：没有根因、验证、预防措施或可识别的专业领域。
