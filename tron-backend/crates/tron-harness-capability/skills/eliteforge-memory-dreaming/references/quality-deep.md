# 深度治理质量

处理 REM 无法确定的冲突、候选堆积、重复、过期、归档、禁用、生效内容演进及结构问题。

## 规则

- 覆盖所有任务目标，按当前 schema 区分已解决、建议、延期及无需操作，并说明证据。
- 严守授权范围，不把仓库事实升级为全局用户偏好或通用政策。
- 分开判断冲突、重复、过时、到期、归档、禁用、合并、拆分、生效演进和结构修复。
- 生效记忆的修改需明确证据证明旧含义错误、不完整或危险地含糊；不能因为几条看起来相关就批量修改。
- 候选按范围、主题和用途聚合，保留最精确且证据最好的项，拒绝弱项和重复项；证据不足时延期或提出待复核建议。
- 过时但仍有历史价值用 `ARCHIVE`，错误、污染、误导或有害用 `DISABLE`。年龄大本身不是禁用理由。

## 写入职责与证明

默认由 CLI 管理持久化。任务协议明确要求 Agent 操作且授权覆盖时，写入只使用当前 `memory_save`，软删除只使用当前 `memory_delete`，不直接写内部存储。

实际保存后核对 `success`、`action`、`memoryCode`、状态及 `rag`，区分存储与索引状态。实际删除后核对 `memoryCode`、`action`、状态、`deleted`、`warnings`。缺少成功返回时交付建议或 `NO_WRITE`，不能模拟副作用。

## 分析重点

- 冲突：分别列出支持和反对证据、权威差异、未解风险，以及建议或实际操作。
- 候选堆积：按范围、主题、用途归组，强化优胜项、拒绝重复项或延期。
- 重复：保留精确内容及有价值的来源，不为了简短丢掉不同用途。
- 过期：判断是否仅时效结束，还是内容已经错误或有害。
- 生效演进：需要明确新证据，建议与执行状态分开。
- 结构健康：只修复实际存在的范围过宽、主体含糊、用途混杂和低价值根节点。

合格：五个同主题候选中建议保留证据最好的一项，其余注明重复原因。新证据可能替代旧规则但尚不足时只提案。

不合格：把项目行为并入全局偏好；只因时间久就禁用；没有成功结果却报告删除或状态更新。
