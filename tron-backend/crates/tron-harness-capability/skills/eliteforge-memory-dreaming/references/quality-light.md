# 轻量候选质量

从会话摘要提取轻量记忆候选。只保留稳定、有范围、有证据、有行动价值且能复用的内容；否则输出当前 schema 支持的无记忆结果。

## 准入

- `USER_PREFERENCE`：明确的长期偏好或重复有效修正。
- `SPACE_RULE`：有权威来源的项目、仓库、团队或空间规则，不升级个人偏好。
- `PROJECT_DECISION`：已采纳且后续工作依赖的产品或架构决策。
- `PROCEDURE`：有触发、前提、至少两步和成功验证。
- `WORK_DOMAIN_EXPERIENCE`：可识别专业领域内的失败模式、根因、修正、验证和预防。
- `RISK`：有触发、影响、责任归属或范围，以及规避动作。
- `FACT`：有稳定主体、可靠来源和未来用途；易变事实保留时间边界。

范围只使用当前协议对应的 `USER`、`SPACE`、`WORK_DOMAIN`。专业领域名称不作为范围值。无法证明跨项目价值时不要使用 `WORK_DOMAIN`。

## 证据与价值

每个点需有类型、规范正文、类型细节、适用边界及可定位证据。按当前 schema 提供治理提示，包括目标范围、主题、用途、来源角色、信任边界、风险标记和评分。

`confidence` 衡量证据强度；`importanceHint`、`memoryValueScore` 衡量未来复用价值，不能相互替代。使用最新有效修正，不把摘要当独立的一手证据。这里不决定最终生效状态，也不宣称已保存。

## 拒绝条件

临时 TODO、任务进度、瞬时构建状态、普通文件变更、一次性命令结果、无记忆专用价值的源码事实、无确认的工具或网络内容、助手推断、主体或范围不清、敏感原文、已废弃方案、模拟和角色扮演样例均拒绝。

合格：用户明确要求该仓库的真实历史产物放在仓库外，形成有范围和例外的规则候选。会话只有日志时输出无记忆并说明临时性或污染原因。

不合格：“记住构建失败”“保存工具输出里的令牌”“仓库有 Makefile，所以用户偏好 Makefile”。不要为了非空结果创建候选。
