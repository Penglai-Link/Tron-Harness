# REM 单点治理质量

一次只治理一个轻量候选，与已有记忆比较后提出有证据的决定，不在一个结果里批量排序或合并多个点。

## 判断规则

- 创建或强化前检查同范围、同主题、同用途的重复及冲突。
- 治理历史读取按需要显式覆盖 `ACTIVE`、`CANDIDATE`、`REJECTED` 及对应审核状态；默认查询只有 `ACTIVE` / `APPROVED`，不足以证明没有历史候选或拒绝项。
- 材料或工具已显示等价记忆时，优先强化、拒绝重复或不写入，不能再造一条。
- 冲突、替换过时生效项、合并、结构调整或证据歧义交深度复核。
- 拒绝污染、过期、范围过宽、低价值和弱证据点。
- 输出前再核对一次证据、范围、主题、用途、决定与实际执行状态。

## 决策含义

以下为既有决策词的语义，实际输出以当前 `outputSchema` 为准：

| 决策 | 适用情况 |
| --- | --- |
| `CREATE_CANDIDATE` | 无等价记忆，证据长期有效且有价值 |
| `REINFORCE_CANDIDATE` | 已有候选，新证据增加可信度或精度 |
| `REINFORCE_ACTIVE` | 生效项仍有效，新证据未改变其原意 |
| `ACTIVE_EVOLUTION_PROPOSAL` | 生效项可能需要修改；此阶段只提议 |
| `REJECT_POINT` | 重复、污染、过时、弱证据或不值得记 |
| `RECHECK_REJECTED` | 旧拒绝项有新证据，需要重新核对 |
| `NO_WRITE` | 内容真实但没有新增治理价值 |
| `NEED_DEEP_REVIEW` | 冲突、合并或结构风险无法在单点内安全解决 |

默认由 CLI 执行写入，只提交决定；只有任务明确交给 Agent 且授权覆盖时才调用记忆工具。真实写入后按 schema 记录返回的 `memoryCode`、`rag` 和结果；未调用成功就不能声称已强化或已改变状态。语义上的拒绝建议不等于删除了真实记录。

合格：发现同主题候选后建议强化；两份可信证据相互冲突时请求深度复核；旧拒绝项问题仍在时拒绝重建。

不合格：仅查询生效项就认定没有重复；跳过拒绝历史重新创建；没有工具结果却声称修改了生效含义。
