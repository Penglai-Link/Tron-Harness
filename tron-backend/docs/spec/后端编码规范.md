# Rust 编码规范

修改后端源码前，必须阅读并遵循本规范。技术依赖和运行方式见[后端技术栈](../后端技术栈.md)。本文件规定新增或修改代码的实现规则；现有代码并未全部采用相同的目录拆分粒度。

## 分层与依赖

后端采用领域驱动设计与六边形架构，依赖方向如下：

```text
入站适配器 → application → domain
出站适配器 → application 定义的接口
app.rs / app/ → 装配适配器、应用服务、路由及 Framework 宿主
```

- `domain` 负责业务模型、不变量、值对象、领域策略、事件和错误。
- `application` 负责用例、输入输出 DTO、事务编排和外部依赖接口（ports）。
- `adapters/inbound` 负责 HTTP 路由、请求解析、独立的接口 DTO 和错误映射。
- `adapters/outbound` 负责 SQLite、加密、文件存储和外部服务等具体实现。
- `app.rs` 及 `app/` 是组合根，负责配置、应用状态、适配器、路由和 Framework 的装配。

存储接口由应用层定义，出站适配器实现接口；领域规则不依赖具体数据库。当前业务存储主要使用 SQLite，图数据和资源文件使用各自的存储适配器。

修改静态数据库结构时，直接更新 `migrations/0001_init.sql` 和初始化测试。不要追加历史补列、旧表重建或数据搬迁分支；业务库与身份登记库分别执行文件中的对应区段。Framework 自有表和按语料创建的动态索引由各自运行时维护。

## 模块布局

采用现代 Rust 模块布局。不要为新的限界上下文或 HTTP 路由组创建 `mod.rs`。

下面列出当前应用管理上下文中的实际路径，子目录仅展示与分层相关的文件：

```text
src/
  domain.rs
  domain/
    app.rs
    app/
      catalog.rs
  application.rs
  application/
    app.rs
    app/
      service.rs
      service/
        projection.rs
        use_cases.rs
  adapters.rs
  adapters/
    inbound/
      http/
        apps.rs
        apps/
          routes.rs
          handler.rs
          request.rs
          error_mapper.rs
    outbound/
      persistence/
        sqlite/
          app_repository.rs
  app.rs
  app/
    routing.rs
```

`domain/app.rs` 和 `application/app.rs` 是模块门面。门面应以 `mod` 声明和受控的 `pub use` 为主，必要时保留少量共享常量或类型别名。调用方使用上下文导出的类型，例如 `crate::domain::app::App`，避免依赖私有模块路径。

当前 `AppRepository` 定义在 `application/app/service.rs`。接口可以与内聚的应用服务放在同一文件；职责增多时再拆为独立模块，不要求每个上下文都机械建立 `port.rs`、`dto.rs` 等文件。

## 拆分规则

- 按业务概念或适配器职责拆分，例如应用目录、会话、工具权限、模型调用和资源摄取。
- 文件包含多个不相关概念、承担多个变更原因时，应拆分。不要继续向庞大的 `entity.rs`、`query.rs`、`policy.rs` 或上下文门面追加实现。
- 只有概念本身需要多个内聚文件时，才增加一层私有子模块。
- 叶子文件聚焦于单个业务概念或适配器职责；通过门面维持稳定的调用路径。
- 复用 Framework 已提供的运行与工具能力；产品业务规则仍由 Tron 的应用层和领域层负责。

## Harness 能力包与工具

- Tron 自有能力包位于 `crates/tron-harness-capability`，Rust 导入名为 `tron_harness_capability`。运行时包 ID 保持 `tron.harness`，修改目录名时不要顺带改变持久化配置中的标识。
- 能力包通过插件注册工具、权限策略和上下文；宿主依赖由 `FrameworkHost` 注入。
- 业务工具元数据修改 `application/agent/tool_catalog.rs` 及同名目录，实现修改 `business_tools.rs` 及同名目录，并检查宿主注册与适配路径。
- 内置技能放在能力包的 `skills/` 内，由构建脚本嵌入。新增、移动或禁用能力包时，检查技能目录、安装和运行时读取的一致性。
- 通用运行循环、交互、命令进程和 PTY 生命周期应复用 Framework。新增宿主适配时，不要在 Tron 中建立第二套运行状态机。

## HTTP、身份与国际化

- 每个 HTTP 接口使用独立的请求和响应 DTO，不直接复用数据库记录或其他接口的 DTO。
- 产品 JSON 响应使用 `ApiResponse<T>`；错误由入站适配器映射为稳定的状态码、业务码和面向用户的消息。
- 受保护的路由通过当前 PersonAI 身份建立请求上下文。不要因为类型名为 `RequestAuthContext` 就假定它执行了本地 token 校验。
- 用户可见消息使用请求语言上下文；目前支持中文和英文，缺省中文。不要依赖进程全局变量，也不要允许模型工具参数覆盖可信请求语言。
- Harness 工具策略通过每轮运行的扩展接收 `TronToolPolicyLocale`；修改权限提示时同步维护中文和英文，并检查并发运行之间的语言隔离。
- 创建 PersonAI SDK 客户端时设置 `X-Product-Code`，确保普通请求和 SSE 请求继承产品标识。
- 修改已登记的 OpenAPI 接口时，同步更新 `src/openapi.rs` 及相关注解；当前文档没有覆盖所有业务 API。

## 文件与执行范围

- Agent 文件、命令工具与外部子代理从同一执行目录解析路径。选定应用/worktree 优先；无项目会话和 Dude 使用各自持久的托管目录。子任务 workingDirectory 由父代理指定并按父代理原有权限验证，省略时继承。显式配置目录不存在时应报错，不能退回后端进程目录。
- `default_branch` 是配置，不代表 worktree 当前检出的分支；需要实际分支时读取 Git 状态。
- 工作区文件和聊天附件通过共享的 `fileRef` 解析，文件导出限制在项目路径范围内。
- Agent 命令省略 `args` 时按命令字符串解释，显式 `args` 按字面 argv 执行。普通命令超过 10 秒后通过任务 ID 跟踪；交互进程使用后端持有的 PTY。
- `chat_ask_user` 答案在上一轮释放会话前保持待处理状态，续跑记录必须持久化答案摘要。

## 禁止事项

- 不在 HTTP 处理器中编写业务规则。
- 不让 `domain` 依赖 `axum`、`rusqlite`、HTTP 状态码、API 响应包装或具体基础设施库。
- 不让出站适配器定义应用层或领域层的接口。
- 不把整个上下文或 HTTP 路由组写入一个庞大的门面或兜底文件。
- 不用测试身份、临时数据库或固定凭据代替正式启动逻辑。

## 验证

修改源码后在仓库根目录运行 `make be-check`。修改能力包时，补充运行 `make harness-capability-check`。

不编写后端测试代码。前端行为在实际运行的应用中检查。

仅修改文档或注释时，检查文件引用、命令名称、示例路径和差异即可。运行 `cargo fmt` 后检查是否改到了无关文件，只保留本次任务范围内的格式调整。
