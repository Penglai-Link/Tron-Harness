# 能力包菜单示例

在能力包 `manifest.json` 的 `resources` 中声明 `tron/navigation.json`，并把该文件打进标准能力包压缩包。压缩包仍须包含 Framework 要求的 `checksums.json`；使用 Framework 的能力包打包器生成，不要修改打包后的内容。

本目录提供一个菜单领域、三个菜单定义及默认编排。菜单编码和领域编码必须使用大写字母、数字或下划线，最长 64 个字符，并避免与其他包或已有菜单重名。

- `domains`：领域编码、中英文名称和说明。包不能占用已有领域，也不能设为默认领域；用户可以在菜单管理中选择默认领域和调整领域顺序。
- `menus`：菜单编码、中英文名称、类型、目标和图标。支持 `Group`、`Internal`、`ExternalLink`、`Widget`。内部页面使用 Tron 已注册的 `pageCode`；这项功能不负责加载能力包自带页面。外链仅支持 HTTP/HTTPS，组件使用 Tron 支持的组件编码。
- `layouts`：以本包声明的领域编码为键，值为菜单编排列表。菜单和父菜单必须由本包声明；父菜单须为 `Group`。同级 `position` 不能重复，层级不能超过系统设置。省略某个领域的编排表示初始为空。
- `childDisplay`：`Inline` 或 `Flyout`，省略时为 `Inline`。只有分组或组件可使用 `Flyout`。

导入后，菜单会自动注册到管理页面。新导入的能力包沿用现有规则，初始为停用状态；启用后才显示侧栏入口。停用会隐藏领域及菜单，但保留编排；再次启用恢复。来源为能力包的菜单定义由包维护，用户可在菜单编排中自由调整位置、分组和显示方式。

升级先检查编码冲突和编排是否合法。未调整过的领域采用新版本默认编排；一旦检测到用户调整，后续升级保留布局，包括用户移除的条目。新菜单仍会出现在菜单定义列表，供用户手动加入。升级沿用能力包导入后的停用规则，需要重新启用。

如果新版移除了菜单，该菜单在各领域中的引用也会移除；其他来源的子菜单会提升到原父级，避免跟随删除。如果新版移除了领域，或卸载整个包，则删除对应领域及其编排关系，其他来源的菜单定义保留。卸载会删除该包提供的全部菜单及各处引用。重新安装按首次安装处理。

导航声明最大为 1 MiB，最多 100 个领域和 1000 个菜单。注册、升级和卸载的导航数据库修改使用事务；升级前的校验会回滚所有试写，不改变当前布局。
